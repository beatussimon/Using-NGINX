NGINX:
The piece of software that runs on a server machine
and can repond to requests on a browser

the same nginx has a load balancer that proxies to those 
other nginx web servers

proxy means to do something on someone elses behalf

So it accepts the requests on behalf of web servers and distributes
the load to the web servers. How? that depends on the algorithm the it
was configured on; it could be a simple logic like the least busy server
, round robbin(distributes the requests in a cyclic manner)

The same nginx server can perform multiple tasks;

caching: 
do the heavy lifting once and
-> store the response
This is another feature of nginx proxy
--> caches the responses from the backend server for frequently 
accesed resources
--->Copies and stores temporarily to improve performance


Exposing all servers to public acess
-> increased surface attack; each publicly exposed server represents
an entry point attackers can target
-> You will have to secure every server(headache)

Instead we just give them 1 server that is publically available; hence:
=> consolidate security
-> minimize exposure
=> centralize access control
=> centralized monitoring and logging	

Using ngix proxy significantly reduces attack surface
and will act as a shield before all those servers


About security 1 important metric is encrypted communication
So frontend will send encrypted communication to the proxy that 
means even if attacker intercepts the message then cant read it 
and only the proxy server can decrypt it 

Better: Nginx fowards the encrypted messages to the web servers and the
server will decrypt it itself

It enforces Https; accepts encrypted traffic and denies unencrypted 
requests

config file:

--> Controls how many parallel processes Nginx spawns(to cause something new, or many new things, to grow or start suddenly: 
The new economic freedom has spawned hundreds of new small businesses.)  to handle client requests.

what is worker process=> Instead of using new connection for every incoming connection , Nginx uses worker processes that
uses many connections using a single-event threaded loop 

What does the number represent:
-> Then value is the number of processes nginx should create
->Each worker process can run independently  and can handle its own set of connections

This configuration influences how well nginx can handle traffic(performance)

Note: should be tuned according to servers hardware (CPU cores) and expected traffic load
In production process its recommended to set the worker processes to be the number of cores and allows
nginx to efficiently use all the cores and values can be defined to auto  where nginx will decide depending on the underlying infrastructure

auto=> nginx will automatically decide the number of cpu cores available on the server and starts a corresponding number of worker
nodes

worker_connections: 41:04

per worker process how many simulatineous connections can be opened
default 512

events{
	worker_processes 1024;
}

=> if you have 1 worker process you can serve 1024 clients, and double if you have 2 worker processes and so on

the higher the value the more worker processes it can handle, the downside is that it increases memory usage cause you have multiple connections
opened at the same time
the actual connections can not exeed the current limit on the max number of open files

CONFIGURING SSL/TLS SECURE CONNECTION;
	step01: obtain the ssl/tls certificate:
ssl certificates enable encryption by using public key cryptography
=>When a user connects to a website via HTTPs, the web server provides its SSl certificates which contains a public key
	The client(browser) uses this key to establish a secure, encrypted session with the server
=> We can generate the self-signed by the server itseif; useful fot testing or internal sites  but not recommended for production

CA-assigned certificate=> issued and authenticated by a trusted certificate authority
			=> CA verifies the identity of the organization requesting the certificate

			=> Trusted by the browsers 


make a directory then go to the directory and run this command:
	open ssl req -x509 -nodes -days	365 -newkey rsa:2048 keyout nginx-selfsigned.key -out nginx-selfsigned.crt

breakdown:
openssl req -> Initiate a certificate generation process
-x509 => Tells OpenSSL to output a certificate in this standard certificate format
-nodes -> tells OpenSSL not to encrypt the private key with a pass phrase\
-days 365 =. specifies the validity period of the certificate in this case; 1 year
-newkey rsa:2048 => creates a 2048 bit RSA key pair
	RSA=> most commpn public key encryption algorithm



-keyout nginx-selfsigned.key ==> specifies the output file for the generated key
 in this case "nginx-selfsigned.key"
-keyout nginx-selfsigned.key ==> specifies the output file for self signed certificate	 in this case "nginx-selfsigned.crt"



Private key: must be kept secret and never shared publicly
	used to decrypt data

Public key: shared with clients to encrypt data

You will then provide some additional info and the files for public key and private key will be generated
